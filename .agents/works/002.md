# Sprint Planning Mechanism - Implementation Checklist

## Overview
Create a new standalone page `sprint-planning.php` with drag-and-drop interface to bulk add/remove USORs to/from sprints.

## Requirements
- **Page**: `sprint-planning.php` (new standalone page)
- **UI**: Cross-list drag-and-drop (jQuery UI Sortable)
- **Source Area (Left)**: 
  - Sprint selector dropdown (backlog + all sprints in project)
  - Text search filter
  - Shows USORs from selected source
- **Target Area (Right)**:
  - Selected sprint's current USORs
  - Unidirectional: drag from source → target to add
  - Remove via button/icon on each USOR in target
- **Sprint Selection**: Dropdown on page (not URL param)
- **Filters**: Independent (no shared filter mechanism)
- **Operations**: Bulk add USORs to sprint, bulk remove USORs from sprint

## Technical Implementation

### Backend (API Endpoints Needed)
- `GET /api.php/milestones/{id}/userstories` - Get USORs in a sprint
- `GET /api.php/userstories?project={id}&milestone=0` - Get backlog USORs (no sprint)
- `GET /api.php/userstories?project={id}&milestone={sprint_id}` - Get USORs in specific sprint
- `PATCH /api.php/userstories/{id}` - Update USOR milestone (add/remove sprint)

### Frontend Files to Create/Modify
1. **New**: `sprint-planning.php` - Main planning page
2. **New**: `assets/app-sprint-planning.js` - Planning page JavaScript
3. **Modify**: `app/layouts/main_navbar.php` - Add link to planning page
4. **Modify**: `sprints.php` - Add "Planning" button/link

### UI Components
- Sprint selector dropdown (project-scoped)
- Source area: Search input + USOR list (draggable)
- Target area: USOR list (droppable, with remove buttons)
- Save/Apply button to commit changes
- Progress indicator for bulk operations

### Drag-and-Drop Logic (jQuery UI Sortable)
- Connect source list to target list
- On drop: queue USOR for milestone update
- On remove click: queue USOR for milestone removal (set milestone=0)
- Batch execute on "Save Changes"

## API Response Handling
- Taiga API returns `milestone` field on userstories (null or sprint ID)
- Backlog = milestone is null or 0
- Update: PATCH `/userstories/{id}` with `{ milestone: sprintId }` or `{ milestone: null }`
- Version field required for PATCH (optimistic locking)

## Data Structures
```javascript
// Pending changes queue
pendingChanges = {
  additions: [{ usorId, version, targetSprintId }],
  removals: [{ usorId, version }]
}
```

## Error Handling
- Version conflict: re-fetch USOR and retry
- Network error: show toast, keep in queue
- Partial success: report counts, allow retry failed
